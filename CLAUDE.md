# Swarm Vanguard

Original mobile-first 3D lane shooter for the browser (Vite + TypeScript + Three.js). The squad auto-advances and
auto-fires; the player steers sideways, picks gates, shoots blocks and survives hordes and bosses. See `README.md`
for the player-facing rules and `ASSETS.md` for how art/audio are generated.

The user chats in Norwegian; all in-game text is English. Small private project: **commit and push to `origin/main`
after each commit** (the user has said this is fine). Pushing to `main` deploys to GitHub Pages via
`.github/workflows/deploy.yml`.

## Commands
- `npm run dev` dev server (LAN reachable, open it on a phone) · `npm test` vitest (sim) · `npm run e2e` Playwright
  (phone viewport, inputs, draw-call/triangle budget) · `npm run build` typecheck + production build.
- `npm run balance [seeds]` headless bot win rates per level (pass `all` as 2nd arg to include slow bonus levels).
- `npx tsx tools/tune.ts [minBal] [ids]` re-tunes horde size per level into `src/levels/tuned.json` (~15 min for all, run it in the background; pass ids like `5,7` to retune only those).
- Visual feedback loop: `node tools/shots.mjs <levelId> <seed> <ticks,..> <balanced|x> [theme 0-3] [dpr]` writes
  `screenshots/*.png`; `tools/boss-shots.mjs`, `tools/menu-shot.mjs`. **Look at the screenshots** after visual changes.
- Other tools: `trace.ts` (squad size over time per policy), `scan.ts` (win rate vs k), `jackpot-timing.ts`,
  `pin-test.ts`, `sim-perf.ts`, `render-perf.mjs`, `weapons.ts`, `lengths.ts`.
- URL params: `?level=<id>&seed=&speed=&autostart=1&autoplay=balanced|greedy-expand|pure-fight|naive&theme=0-3`.
  `window.__game` exposes `getState/step/setInput/stats/restart/stress/viewMismatches/renderer/raw`.

## PWA / hosting (home-screen install is the main way the user plays)
- `public/manifest.webmanifest`, `public/sw.js`, `public/icons/*` (generated by `node tools/make-icons.mjs`; edit the SVG there).
- `npm run build` ends with `tools/stamp-sw.mjs`: per-deploy cache name AND the list of every `dist/assets` file, which the
  worker precaches on install (so the first launch and every update work offline at once). `npm run pwa-check` proves
  offline start for a first install and for an A->B update. The worker is only registered in production builds.
- Install popup: `src/ui/install.ts` (Chrome `beforeinstallprompt` -> our own sheet; iOS -> manual Share steps; remembers
  "Not now" for a week; only on the menu). Layout uses `--sat/--sab` (safe-area insets) so the HUD clears the iPhone notch.
- Hosted on GitHub Pages under `/swarm-vanguard/`; `base` is relative, so keep all asset paths relative (`./icons/...`).

## Siege (arena) levels
- `level.arena` (see `ArenaDef` in `src/sim/level.ts`) switches on every arena rule in `sim/game.ts`; lane levels never take those
  branches (proven by an identical `npm run balance`). Fixed camera, free 2D movement (`Input.targetY`), timed `wave` spawns that
  start awake, a fixed bottom leak line, `tile` pickups, and a `keystone` block whose destruction wins (`collapse` event).
- `src/levels/siege.ts` builds the sieges (ids 201-205, `bonus: 'siege'`, placed after each world's jackpot/swarm/blast level). Siege 205 has `twin: true` (two pillars, both must fall; `game.keystoneInfo()` sums them for the HUD bar, bots walk to the nearest).
  Difficulty `k` scales the **keystone HP** (time is the difficulty: escalating waves are the clock); sieges are sized by hand and
  skipped by `tune.ts`. `npx tsx tools/siege-check.ts <id>` runs every policy through one and checks that all runs end.
- Bots: `policies[name]` dispatches to a siege version when `g.level.arena` is set (`park` = stand under the pillar). In a siege
  both `naive` and `park` must lose. Always feed the sim through `toInput(policy(g))`.
- Render: `world.applyArena`, a static camera in `renderer.render`, `crowd.setArena` (decorative mass under the roof sized by
  `game.reserve()`), keystone/tiles in `props.ts`, keystone bar in the HUD, `Controls.yRange` for vertical drag/WASD.
- Progress is derived from cleared levels (save v2, `unlockedCount` in `meta/save.ts`), so inserting levels never shifts it.

## Architecture (the rule that matters)
- `src/sim/` is a **deterministic fixed-step (60 Hz) simulation with no three.js/DOM imports**. The same code runs in
  the browser and headless in Node (bots, tuner, tests). Never import render/DOM code into `src/sim`.
- Stats are `base + modifier list` (`sim/stats.ts`); shop upgrades, pickups and gates are all just modifiers.
- `src/render/` draws the sim: `renderer.ts` (orchestrator, camera, fx routing), `crowd.ts` (instanced units, LOD,
  corpses, flashes), `props.ts` (gates/blocks/barrels), `world.ts` + `themes.ts` (5 worlds; world 5 = jungle with fireflies), `models.ts`
  (procedural figures with body-part ids), `materials.ts` (toon + GPU limb animation via `onBeforeCompile`).
- `src/levels/`: `builder.ts` DSL, `index.ts` (20 levels + 5 bonus levels, ids 101-105; page 2 = worlds 5-8, added one world at a time, `LEVEL_COUNT` is raised only after the world is tuned and screenshotted), `tuned.json` (generated).
- `src/sim/bots.ts` are shared by the tuner and `?autoplay=`. `src/meta/` = versioned save, shop upgrades, settings.

## Rules learned the hard way
- **Render-only changes must leave `npm run balance` output identical.** Sim changes go in one batch, then one retune.
- Any new sim mechanic must be playable by `balanced` bot without a new skill, and `k` (horde multiplier in
  `LevelBuilder`) must scale it, otherwise the tuner collapses to the grid floor. The tuner and bots play with the **upgrade profile** (`profileLevels/profileModifiers(progress)` in `meta/upgrades.ts`: the upgrades a typical player owns that far into the game, growing from 0 at level 1 to ~15/20 size+damage, 10/15 rate, piercing and Armory later). `NO_PROFILE=1` runs without. Changing the shop or profile means a full retune (`npx tsx tools/tune.ts 0.8`, >1 h; it only writes `tuned.json` at the very end, and high k at the last levels is slow).
- Levels are addressed by **id** (jackpot/swarm/blast bonus levels 101-105, sieges 201-205); `levelIdx`/array position is play order. Tools must use
  `LEVELS.find(l => l.id === id)`, never `LEVELS[id - 1]`.
- Bullets must spawn in front of a block ahead, or deep crowds shoot over it (regression test exists).
- Hordes placed right after a shoot-block must sit on the opposite side, or the pinned squad is overrun.
- Entity ids restart per `Game`; `renderer.reset()` on every restart (e2e checks level-pair id collisions).
- Performance budget (headless proxy; real-device FPS is unverified): <90 draw calls and <330k triangles with
  300 soldiers + 2000 enemies (e2e test). Crowd uses distance LOD; keep outlines to brutes/bosses only.
- Visual scale of units is render-only (`SOLDIER_SCALE`/`ENEMY_SCALE` in `crowd.ts`); hit boxes live in the sim.
- Pace is `GAME_SPEED` (1.25x sim clock) in `src/main.ts`; weapon ranges are in `WEAPONS` (`sim/game.ts`) and changing
  them needs a retune.
- Elites (`elite` kind, `grind`+`holds` in `ENEMY_DEFS`) stand at the squad, pin it and eat soldiers until killed; swarm carpets use `grid: true` spawns.
- Menu: the big button continues from the furthest unlocked level; tapping a level plays exactly that one.
- Level 1 is the hand-tuned tutorial (free gate first, `tuned.json[1]` set by hand; the tuner skips it unless asked).
  One-time tips (`maybeTip` in `main.ts`) never show while the first-run hint is up.
- If standing still ever wins a level, re-roll its layout: `npx tsx tools/reroll.ts <id>` writes `src/levels/variants.json`,
  then `npx tsx tools/tune.ts 0.8 <id>` re-tunes only that level (levels 5 and 7 needed it).
- The repo is `eivindlie/swarm-vanguard` (public: Pages from a private repo needs a paid plan). Don't change visibility without asking.

## Page 2 (worlds 5+)
- Page 2 ids restart the difficulty scale (`lid` in `generated`); page-1 rows of `npm run balance` must stay identical (compare ids 1-16).
- World 5 Jungle Ruins (17-20): `bulwark` enemy (`armor` 0.3 vs rifle/shotgun bullets; rockets, lasers and blasts ignore armor), Stone Idol boss,
  Blast bonus 105 (barrel chain reactions: barrels caught in a barrel blast go off; rocket splash does not chain, so page 1 is unchanged).
- World 6 Neon City (21-24: `bomber`, Turbo Gates bonus 106, siege 206), world 7 Candy Kingdom (25-28: `jelly`, temporary buff gates OVERDRIVE/HEAVY ROUNDS via `Upgrade.secs` + `Modifier.until`, Candy Vault jackpot 107, siege 207), world 8 Moon Base (29-32: `drone`, Warden Rush boss-rush bonus 108, twin siege 208).
- Page-2 levels use level-relative enemy HP (`hpMul` from `lid`), otherwise the tuner shrinks hordes to nothing.
- Shop (`meta/upgrades.ts`): size 20, damage 20, rate 15, loot 10, Piercing 3, Armory 3 (start with shotgun/rocket/laser). Levels past the old cap cost steeply more (`tail`).
- Sieges are scaled by world (`grow` in `siege()`); with the profile, naive and park must lose, balanced win.
